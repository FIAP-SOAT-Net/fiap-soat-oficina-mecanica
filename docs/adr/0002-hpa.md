# ADR 0002 — Escalonamento (HPA)

Status: Accepted
Decisão: Usar Horizontal Pod Autoscaler (HPA) em Kubernetes para escalonamento baseado em CPU e métricas customizadas (latência/throughput).

Contexto

A aplicação deverá escalar horizontalmente em produção para suportar picos de carga. O cluster alvo é EKS (ou outro provedor Kubernetes).

Alternativas consideradas

- Escalonamento manual: simples, mas não responsivo a picos.
- Escalonamento vertical (mais CPU/RAM): limitado e causa downtime potencial.
- HPA com métricas customizadas (Prometheus Adapter / Cloud Provider Metrics): automático e responsivo.

Decisão

- HPA configurado com métricas padrão (CPU) e, quando necessário, métricas personalizadas (ex.: filas, latência) via Prometheus Adapter ou métricas do cloud provider.

Motivação

- HPA é padrão no Kubernetes e integra-se com deploys automáticos e observabilidade.
- Permite otimização de custos e resposta automática a variações de carga.

Impactos

- Necessidade de configurar métricas (Prometheus + Adapter) para usar métricas customizadas.
- Deploys devem incluir probes (readiness/liveness) e limites/requests corretos para funcionar bem com HPA.
- Estratégia de limites e requests precisa ser definida por ambiente.

Recomendações

- Definir requests/limits por serviço antes de habilitar HPA em produção.
- Usar HPA combinado com Cluster Autoscaler para aumentar nós quando necessário.
- Monitorar comportamento e ajustar thresholds gradualmente.
